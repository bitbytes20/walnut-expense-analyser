**Then modify `src/main/import/icici-parser.ts`:**

Currently the ICICI parser either succeeds or throws/rejects the entire file. Modify it to:

1. During row iteration, wrap each row's parsing in a try/catch (or validation check).
2. When a row fails to parse (invalid date format, non-numeric amount, missing required field), instead of rejecting the whole file, collect a `ParseRowError` object:
   - `rowNumber`: 1-based row number in the source file (header row is typically row 1, so data starts at row 2+)
   - `expected`: human-readable description of what was expected. Examples:
     - `"date in DD/MM/YYYY format"` for date parse failure
     - `"numeric amount value"` for amount parse failure
     - `"non-empty transaction description"` for missing narration
   - `found`: the actual raw value that was encountered, quoted. e.g. `"'N/A'"`, `"'abc'"`, `"''"`
   - `suggestion`: actionable fix suggestion. Examples:
     - `"Remove this row or correct the date value."` for bad date
     - `"Ensure the amount column contains a number."` for bad amount
     - `"Add a description to this row or remove it."` for missing narration
3. After iteration, if `parseErrors.length > 0`, set `stagedFile.parseErrors = parseErrors` on the resulting `StagedImportFile`. The file status remains `'rejected'` when errors exist, but now carries detailed error info.
4. If all rows parse successfully, `parseErrors` remains `undefined`.

**Verify `import-coordinator.ts` `replaceStagedFile`** (skeleton added in Plan 01):
- Ensure it finds the entry in `this.stagedRecords` by `stagedFileId`, removes it.
- Calls the same internal parse method used by `stageFilePaths` for the single new file.
- Inserts the new parse result into `this.stagedRecords` at the same position.
- Returns the full `StageImportFilesResult` from all current `stagedRecords`.
- If `stagedFileId` not found, throw an error.
