## Color

Inherited from `tokens.css`. No new colors introduced.

| Role | Token | Light Value | Dark Value | Usage |
|------|-------|-------------|------------|-------|
| Dominant (60%) | `var(--color-bg)` | `#F5F1E8` | `#171813` | Page background beneath all new surfaces |
| Secondary (30%) | `var(--color-surface)` | `#E2D7C5` | `#26271F` | Bulk action bar background (frosted: `rgba(245, 241, 232, 0.96)`), filter drawer preset section background |
| Accent (10%) | `var(--color-accent)` | `#0F766E` | `#0F766E` | Reserved elements only (see below) |
| Destructive | `var(--color-destructive)` | `#B42318` | `#B42318` | Import error row label, error detail "what was expected vs found" field labels |

Accent (`var(--color-accent)`) is reserved for:
1. The "Apply" / primary confirm button inside the bulk category/tag dropdowns in the transaction bulk action bar
2. The "Save" confirm button that appears inline in the filter drawer when naming a new preset
3. The kicker label "Bulk actions" text in `TransactionBulkActionBar` (follows `ReviewBulkActionBar` existing pattern)
4. Focused checkbox outline ring (`:focus-visible` outline — `2px solid var(--color-accent)`)
5. Focused preset list item restore button (primary restore pill when focused or hovered)

Accent is NOT used for:
- Checkbox checked fill (use `var(--color-ink)` fill or browser native checked state with `accent-color: var(--color-accent)`)
- Bulk action secondary buttons (approve, dismiss, tag entry area)
- Import error status badges (use destructive palette)
- The "View reason" toggle within `StagedFileRow` (secondary styling, `var(--color-ink)` text)
- Preset rename/delete controls (use `var(--color-ink)` text, secondary styling)

Destructive (`var(--color-destructive)`) is reserved for:
- The status badge and error icon on a `StagedFileRow` with `status: 'rejected'` and parse errors
- The error detail panel's "Expected" / "Found" contrast labels (muted destructive — `rgba(180, 35, 24, 0.72)` color for the label text, not the full token)
- Preset delete button (on hover only — transition to `var(--color-destructive)` text on hover, default `var(--color-muted)`)

Color source: `src/renderer/styles/tokens.css` — all values read directly.

## Visuals

Primary focal point per surface:

- **Transaction bulk action bar:** "N selected" heading (20px, 600) is the dominant read. Action controls are secondary. The bar uses the existing `ReviewBulkActionBar` frosted surface pattern — `rgba(245, 241, 232, 0.96)` background with `var(--shadow-panel)` — so it floats visually above the table without competing with the data.
- **Filter preset section (inside filter drawer):** Preset list items use a flat pill row shape with 8px vertical padding. The preset name is left-aligned body text; "Restore" is a right-aligned secondary text button. No card chrome — the list reads as a simple ordered menu.
- **Import error detail expansion:** Error detail panel is inlined directly below the `StagedFileRow` that triggered it. It uses `var(--color-surface)` background with a `3px solid var(--color-destructive)` left border inset — the same visual grammar as the Danger Zone section in Settings — to make the destructive context legible without alarming repetition.
- **Review queue keyboard shortcut hints:** No visual addition. Shortcut hints (`A` / `R` / `↑` / `↓`) appear in the existing `title` attribute on action buttons, consistent with Phase 8 Ctrl+1–8 pattern.

## Interaction Contracts

### Transaction Multi-select (WORKFLOW-01, WORKFLOW-02, WORKFLOW-03)

- **Checkbox column:** Permanent leftmost column in `TransactionLedgerTable`. Column width: 40px. No hover-reveal or toggle-mode (D-01).
- **Header checkbox:** Indeterminate-state `<input type="checkbox">` managed via `ref` — `indeterminate = someSelected && !allSelected`. `aria-label="Select all on this page"`. Covers current page only (D-02).
- **Row checkbox:** `<input type="checkbox">` per row. `aria-label="Select {row.description}"`. Shift+click range-select uses anchor ref pattern from RESEARCH.md §Pattern 1.
- **Range-select visual feedback:** Rows within an active shift-select range receive a transient `background: rgba(15, 118, 110, 0.06)` tint on mouseenter while shift is held. On mouseup the range finalizes. No animation needed.
- **Selection reset rule:** Selection clears on page navigation and filter/search submission. Selection does NOT clear on sort column change within the same page (D-02 intent).
- **Bulk action bar:** `TransactionBulkActionBar` renders sticky (below table header, above table body) when `selectedIds.size > 0`. Disappears when selection clears (D-03). Uses `position: sticky; top: 0; zIndex: 10` with `var(--shadow-panel)`.
- **Bulk category assignment:** Inline dropdown trigger inside the bar — label: "Assign category". Opens a list of category names. Selecting one immediately calls the bulk IPC handler. Confirmation copy appears in the bar: "N transactions updated." for 3 seconds then clears. No modal (D-04).
- **Bulk tag assignment:** Inline text input + "Apply tag" button inside the bar — follows D-05 and the existing `ReviewBulkActionBar` tag input pattern. Input: `minHeight: 44`, pill shape, `placeholder="Add tag to selected"`. Confirmation copy: "Tag applied to N transactions." for 3 seconds. Single tag per apply action; user may apply multiple times.

### Review Queue: Bulk Actions (WORKFLOW-04)

- **Bulk approve/dismiss:** Already wired in `ReviewBulkActionBar`. This phase extends it to display a count-summary message when mixed-state results occur (D-06).
- **Mixed-state result copy:** `"{n} approved, {m} skipped (import gate still active)"` — rendered as inline text in the bulk action bar for 4 seconds after the action resolves, then fades. Rendered at `fontSize: 14, color: var(--color-muted)`.
- **No pre-action prompt:** Mixed-state bulk approve executes immediately. The count summary is the only feedback (D-06).

### Review Queue: Keyboard Shortcuts (WORKFLOW-07)

- **`A` key:** Approve the currently focused review queue item. Single-key, no Ctrl modifier (D-07).
- **`R` key:** Reject the currently focused review queue item. Single-key, no Ctrl modifier (D-07).
- **`↑` / `↓` arrow keys:** Navigate between review queue items, moving focus up or down (D-08).
- **Focus scope guard:** A/R/↑/↓ listeners are only active when the `ReviewQueueScreen` component is mounted and the event target is not an `INPUT`, `TEXTAREA`, or `contentEditable` element. Uses same guard pattern as `App.tsx` global shortcuts (Phase 8 precedent).
- **Focus auto-advance (Claude's Discretion):** After `A` or `R` executes successfully, keyboard focus automatically advances to the next item in the queue list. If the resolved item was the last in the list, focus stays on the new last item (or moves to the empty state message if the list empties).
- **Visual keyboard focus indicator:** The focused queue item receives `outline: 2px solid var(--color-accent); outline-offset: 2px` on its container. The focused item also receives a subtle `background: rgba(15, 118, 110, 0.04)` tint on the row.
- **Existing Ctrl+1–8 shortcuts are unchanged.** A/R are scoped to review queue context only. No collision with existing global shortcuts.

### Import Error Diagnostics (WORKFLOW-05, WORKFLOW-06)

- **"View reason" button on `StagedFileRow`:** Already exists for `status: 'rejected'`. Phase 9 extends click behavior: if `file.parseErrors` array is present and non-empty, the button label changes to "View error details" and clicking toggles inline expansion (D-10). If `parseErrors` is absent (generic reject reason), the button routes to the existing `ReasonPanel` as before — no regression.
- **Inline error expansion panel:** Appears directly below the `StagedFileRow` using a CSS `height` transition (collapse/expand). Panel uses `var(--color-surface)` background, `3px solid var(--color-destructive)` left border, `var(--space-lg)` padding.
- **Error row item layout:** Each parse error renders as a small card within the panel:
  - Row number label: `"Row {n}"` — `fontSize: 12, fontWeight: 600, color: var(--color-muted)` — top-left
  - What was expected vs found: two labeled fields (`Expected:` / `Found:`) — `fontSize: 14` body
  - Suggested fix: `fontSize: 14, fontStyle: italic, color: var(--color-muted)` — below the two fields
  - Separator: `borderBottom: 1px solid var(--color-border)` between error items
- **"Replace file" / retry button:** Appears at the bottom of the expanded error panel. Label: "Replace with corrected file". Secondary styling (border button). Clicking opens an Electron native file picker. The selected file replaces the rejected file in the staging list in-place — no navigation away (D-11). Other staged files and batch context are preserved.
- **Retry in-progress state:** "Replace with corrected file" button shows loading state (button `disabled`, label "Replacing…") while the IPC call is pending.

### Filter Presets (WORKFLOW-08, WORKFLOW-09)

- **Preset section location:** Top of `TransactionFilterDrawer`, above the existing filter controls. A horizontal rule (`var(--color-border)`) visually separates presets from active filters below (D-13).
- **Preset list (populated state):** Scrollable flat list of saved presets. Each row:
  - Left: preset name — `fontSize: 14, fontWeight: 400, color: var(--color-ink)`
  - Right: "Restore" button — secondary pill (`fontSize: 12, minHeight: 32, padding: 0 12px`). Click restores all filter values from the preset immediately.
  - Far right: trash icon (`lucide-react Trash2`, 14px) — `color: var(--color-muted)`, transitions to `var(--color-destructive)` on hover. Click prompts inline confirm (see below).
  - Rename: double-click on preset name converts it to an inline `<input>` with the current name pre-filled. `Enter` or blur confirms. `Escape` cancels.
- **Preset list (empty state — Claude's Discretion):** Thin helper note: `"No presets saved yet. Set your filters then save them as a preset below."` — `fontSize: 13, color: var(--color-muted), fontStyle: italic`. Vertically compact; does not inflate the drawer height.
- **"Save as preset" button:** Bottom of the filter drawer. Secondary pill button. Label: "Save as preset". Only shown when at least one filter is active (to avoid saving empty filter sets).
- **Naming inline input (D-14):** Clicking "Save as preset" replaces the button inline with a text `<input>` + "Save" button row. `<input>` `placeholder="Preset name"`, `autoFocus`, `maxLength={64}`. "Save" is accent-primary and disabled until input is non-empty. `Escape` cancels and restores the "Save as preset" button.
- **Delete confirmation:** Inline — clicking the trash icon shows a mini confirm row in-place: `"Delete "{name}"?"` with "Delete" (destructive text) and "Cancel" (muted text) side by side at `fontSize: 13`. No modal overlay.
- **Preset storage:** SQLite via IPC (D-12). Preset list is fetched on filter drawer open and on any CRUD operation. No localStorage fallback.

## Accessibility Contract

1. All interactive elements reach via Tab in logical document order.
2. Focus ring visible on every focusable element (`:focus-visible` — `outline: 2px solid var(--color-accent); outline-offset: 2px`).
3. Checkboxes have `aria-label` on each row checkbox and `aria-label="Select all on this page"` on the header checkbox.
4. Select-all header checkbox uses `ref.current.indeterminate` for the indeterminate state (React does not support declarative `indeterminate`).
5. Bulk action bar: `role="region"` with `aria-label="Bulk actions"` on the container; confirmation messages rendered in an `aria-live="polite"` region so screen readers announce results without focus move.
6. Review queue keyboard focus: focused item has `aria-current="true"` or equivalent programmatic focus management so screen readers read the focused item.
7. A/R keyboard shortcut guard: handlers check `event.target.tagName` is not INPUT, TEXTAREA, or contentEditable before processing (same guard as Phase 8 global shortcuts).
8. Import error detail panel: `role="region"` with `aria-label="Parse error details for {filename}"`. Error items within are `<li>` elements inside a `<ul>`.
9. Filter preset rename inline input: `aria-label="Rename preset"`, `autoFocus` on mount. Escape cancels without data loss.
10. Delete confirm strip: "Delete" button has `aria-label="Delete preset {name}"` to disambiguate from other delete controls if multiple presets are listed.
