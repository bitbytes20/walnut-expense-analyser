# Plan 02: Transaction Edit Auditing & Inline UX

## Objective
Enforce atomic auditing for all transaction edits and expose this contextual history directly within the transaction UI.

## Overview
Every edit to a transaction must create a durable record capturing the before/after state. Both mutation and audit event must save in a single SQLite transaction to avoid out-of-sync states.

## Tasks

Modify the `updateTransaction` (or equivalent method handling user edits in `db.ts`) to use a `db.transaction()` wrapper. The transaction must contain:
