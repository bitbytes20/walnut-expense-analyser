# Plan 03: Redacted Diagnostics Export

## Objective
Establish secure, privacy-preserving pipelines for exporting application data and SQLite dumps.

## Overview
To provide high-quality support without compromising the offline-first privacy posture, the app must generate two types of diagnostics: "Full" (only viewable locally by the owner) and "Redacted" (safe to share).

## Tasks

<task>
<read_first>
- `src/main/diagnostics/diagnostics.ts` (create new)
- `src/shared/contracts/diagnostics.ts` (create new)
</read_first>
<action>
Create a new module `diagnostics.ts` in `src/main/`. Implement a pure redaction function `redactDiagnosticTransaction(tx: Transaction): RedactedTransaction` that explicitely overwrites sensitive string fields: `description: '[REDACTED]'`, `reference: tx.reference ? '[REDACTED]' : null`, `tags: tx.tags.length > 0 ? ['[REDACTED]'] : []`. It must keep all numeric `amount_minor` and `category_id` values exactly as they are.
</action>
<acceptance_criteria>
- `diagnostics.ts` contains `redactDiagnosticTransaction`.
- The redaction does not wipe out amounts or category IDs.
</acceptance_criteria>
</task>

<task>
<read_first>
- `src/main/diagnostics/diagnostics.ts`
- `src/main/persistence/db.ts`
</read_first>
<action>
Implement the `generateDiagnosticsBundle(type: 'full' | 'redacted')` pipeline. If `redacted`, it should stream all transactions from `db.ts` through `redactDiagnosticTransaction` and serialize to JSON. If `full`, it skips redaction. Both bundles should also include the `audit_events` ledger and system metrics (e.g., node version, OS, app version). Return the generated JSON string.
</action>
<acceptance_criteria>
- `generateDiagnosticsBundle` exists and accepts a `type` parameter.
- When `type === 'redacted'`, the returned JSON string does not contain unmasked `description` text.
</acceptance_criteria>
</task>
