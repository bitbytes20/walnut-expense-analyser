## Color

Inherited from `tokens.css`. No new colors introduced.

| Role | Token | Light Value | Dark Value | Usage |
|------|-------|-------------|------------|-------|
| Dominant (60%) | `var(--color-bg)` | `#F5F1E8` | `#171813` | Settings page background |
| Secondary (30%) | `var(--color-surface)` | `#E2D7C5` | `#26271F` | Action cards, section cards, backup note panel, crash log note |
| Accent (10%) | `var(--color-accent)` | `#0F766E` | `#0F766E` | Reserved elements only (see below) |
| Destructive | `var(--color-destructive)` | `#B42318` | `#B42318` | Danger Zone section buttons only |

Accent (`var(--color-accent)`) is reserved for:
1. The primary Backup action button ("Create Backup") — only one primary per section
2. The "Save Changes" / confirmation button in the Change PIN flow
3. Toggle `checked` state indicator (background when a feature flag is enabled)
4. The type-to-confirm button when the typed text matches the required word exactly

Accent is NOT used for:
- Section headings or descriptive text
- Idle timeout selector options
- Restore button (secondary styling — `var(--color-bg)` background, `var(--color-ink)` text)
- Feature flag toggle track in unchecked state (use `var(--color-border)`)

Destructive (`var(--color-destructive)`) is reserved for:
- "Clear Transactions" button (Danger Zone)
- "Reset App" button (Danger Zone)
- Danger Zone section heading visual treatment (left border or background tint, 8% opacity destructive)

Color source: `src/renderer/styles/tokens.css` — all values read directly, no inference.

## Interaction Contracts

### Settings Page Layout

- Single scrollable page, `maxWidth: 720`, `margin: 0 auto` — matching current `SettingsScreen.tsx` root style
- Section order (top to bottom, D-02): Preferences → Security → Backup → Support → Feature Flags → Danger Zone
- Each section wrapped in `<section aria-labelledby="{id}-heading">` with an `<h2>` heading
- Visual section separator: `borderTop: '1px solid var(--color-border)'` with `paddingTop: var(--space-xl)` between sections
- No tab or sidebar navigation (D-01)

### Theme Toggle (Preferences section)

- Two-option control: "Light" / "Dark" / "System" — segmented button group, not a `<select>`
- Active option: filled with `var(--color-accent)`, white text
- Inactive option: `var(--color-surface)` background, `var(--color-ink)` text, `var(--color-border)` border
- Keyboard: focus ring on each segment; arrow keys cycle options; Space/Enter activates focused option
- Applies `data-theme="light"` / `data-theme="dark"` on `<html>` immediately on selection; removes attribute for "System" (falls back to `@media prefers-color-scheme`)
- Persisted to `app_settings` via `setAppConfig({ theme })` IPC on change

### Idle-Lock Timeout (Preferences section)

- `<select>` control with options: 5 minutes, 15 minutes (default), 30 minutes, Never
- Label: "Lock after inactivity"
- Helper text below: "The app will lock itself after this period of keyboard and mouse inactivity." (14px, `var(--color-muted)`)
- Persisted to `app_settings` via `setAppConfig({ idleLockTimeoutMs })` IPC on change
- Value mapping: `5 * 60_000`, `15 * 60_000`, `30 * 60_000`, `0` (never)

### Change PIN (Security section)

- Triggered by "Change PIN" action button (secondary styling)
- Opens an inline card below the button row (not a modal) with three PIN inputs: Current PIN, New PIN, Confirm New PIN
- All inputs type `password`, inputMode `numeric`, pattern `[0-9]*`, minLength 6
- Validation: new PIN must be 6+ digits; confirm must match new PIN
- Error state: inline error text below the mismatched field in `var(--color-destructive)`, 12px, 400 weight
- Success state: inputs collapse; brief success message "PIN updated successfully" for 3 seconds before returning to idle
- CTA button: "Update PIN" — accent primary styling, disabled until all three inputs are valid

### Backup Section

- Two action cards (reusing established `actionCard` pattern from `SettingsScreen.tsx`):
  1. **Create Backup** — primary accent button; label: "Create Backup"; description: "Saves an AES-256 encrypted backup of your data. Use your current PIN to decrypt it."
  2. **Restore from Backup** — secondary button; label: "Restore from Backup"; description: "Import a .wbk backup file. You will need the PIN used when the backup was created."
- Backup file format: `.wbk` extension (D-05, Claude's discretion — `.wbk` is short, unambiguous, app-specific)
- On "Create Backup": opens OS native save dialog (Electron `dialog.showSaveDialog`); shows in-progress loading state on button during encryption; shows "Backup saved" success message inline for 3 seconds
- On "Restore from Backup": opens OS native open dialog; shows inline PIN input field after file is selected ("Enter the PIN that was active when this backup was created"); decrypt/restore runs with loading state; on success shows "Backup restored. Set a new PIN to continue." and routes to PIN setup flow; on failure shows "Wrong PIN or corrupted backup file. Check the file and try again."
- Warning note below both cards: `role="note"` panel — "Backup files are owner-only and not safe to share. Unlike the redacted diagnostics bundle, backup files contain all your transaction data." Panel styled as `var(--color-surface)` background, `var(--color-border)` border, 8px left-border using a `rgba(180, 35, 24, 0.20)` amber-warning tint — no destructive color, this is informational not an error.

### Feature Flags Section (labelled "Lab" in the UI heading)

- One toggle row for Phase 8 release 1 (D-11):
  - Label: "AI Summaries" (14px, 500 weight)
  - Description: "Show a narrative AI summary on the dashboard. Off by default. Requires an external AI service when enabled." (12px, 400, `var(--color-muted)`)
  - Toggle: custom CSS toggle switch (pill shape); checked state uses `var(--color-accent)` track; unchecked uses `var(--color-border)` track; thumb is `#fff`; toggle is keyboard focusable with `role="switch"` and `aria-checked`
  - Off by default (D-11)
  - Persisted via `setAppConfig({ featureFlags: { aiSummaries } })` IPC immediately on toggle
- Section has a low-contrast note: "Features in Lab are experimental. They may change or be removed." (12px, `var(--color-muted)`)

### Danger Zone Section

- Section heading "Danger Zone" with a `borderLeft: '3px solid var(--color-destructive)'` inset, `paddingLeft: var(--space-md)`
- Section background: `rgba(180, 35, 24, 0.04)` tint on the section container
- Two action cards:

  1. **Clear Transactions**
     - Description: "Permanently deletes all transaction records and their associated audit events. Your categories, rules, and account profile are kept."
     - Button: "Clear Transactions" — destructive styling (`var(--color-destructive)` background, white text)
     - Confirmation: single dialog — "Clear all transactions? This cannot be undone. Your categories, rules, and profile will not be affected." with "Clear Transactions" (destructive) / "Keep Transactions" buttons

  2. **Full App Reset**
     - Description: "Wipes everything and returns the app to first-run onboarding. This cannot be undone."
     - Button: "Reset App" — destructive styling
     - Confirmation: type-to-confirm flow — modal with instruction text "Type RESET to confirm", controlled `<input>` tracking match; "Reset App" confirm button disabled until input value exactly equals `RESET`; on confirm: runs reset, routes to onboarding

### Keyboard Shortcuts

Global shortcuts (centralized in `App.tsx` keydown listener, D-07, D-08):

| Shortcut | Action |
|----------|--------|
| Ctrl+1 | Navigate to Dashboard |
| Ctrl+2 | Navigate to Import workspace |
| Ctrl+3 | Navigate to Transaction ledger |
| Ctrl+4 | Navigate to Import history |
| Ctrl+5 | Navigate to Categories & Rules |
| Ctrl+6 | Navigate to Audit ledger |
| Ctrl+7 | Navigate to Settings |
| Ctrl+8 | Lock the app (triggers `window.walnut.lockNow()`) |

Guard: listener checks `event.target.tagName !== 'INPUT' && event.target.tagName !== 'TEXTAREA' && !event.target.isContentEditable` before handling (Pitfall 3 from RESEARCH.md).

Shortcut surface: `title` attribute on each sidebar nav button includes the shortcut hint, e.g. `title="Dashboard (Ctrl+1)"` (D-09). No dedicated shortcuts panel.

In-screen action shortcuts (Claude's discretion per D-10):

| Shortcut | Scope | Action |
|----------|-------|--------|
| Escape | Any open drawer or modal | Close without saving |
| Enter | Confirmation dialogs (single-step) | Confirm action (when confirm button is focused) |
| Escape | Type-to-confirm input is active | Cancel and close modal |
| Ctrl+S | Settings screen, Change PIN card is open | Submit PIN change (same as clicking "Update PIN") |

Note: Ctrl+S does not conflict with any Electron/Chromium default. Ctrl+W (close tab), Ctrl+R (reload), Ctrl+F (find), Ctrl+T (new tab), Ctrl+N (new window), Ctrl+L (address bar), Ctrl+U (view source), Ctrl+P (print) are all avoided.

Tab/focus order: all interactive elements (buttons, selects, toggles, inputs) are natively focusable or have `tabIndex={0}` with `role` and `aria-*` attributes. Focus ring uses the browser default enhanced with `outline: 2px solid var(--color-accent)` and `outline-offset: 2px` on `:focus-visible`.

## Accessibility Contract

Minimum requirements for ACCS-01:

1. All interactive elements reach via Tab in logical document order
2. Focus ring visible on every focusable element (`:focus-visible` — `outline: 2px solid var(--color-accent); outline-offset: 2px`)
3. Toggle switches carry `role="switch"` and `aria-checked={checked}`
4. Segmented theme control: each button has `aria-pressed={isActive}` and descriptive `aria-label`
5. Modals trap focus within the overlay; Escape closes; `aria-modal="true"` and `aria-labelledby` on the container
6. Type-to-confirm input: `aria-label="Type RESET to confirm"`, `aria-describedby` pointing to instruction paragraph
7. Section headings are `<h2>` elements with matching `id` values for `aria-labelledby` on their `<section>` wrapper
8. Action cards that are loading: button set to `disabled`, label updated to reflect loading state (e.g. "Creating backup…")
9. Success messages injected as `aria-live="polite"` regions so screen readers announce them without focus move
10. Sidebar shortcut hints: `title` attribute on each nav button includes shortcut in parentheses, e.g. `title="Settings (Ctrl+7)"`
