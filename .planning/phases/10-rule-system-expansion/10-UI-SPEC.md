## Color

Inherited from `tokens.css`. No new colors introduced.

| Role | Token | Light Value | Dark Value | Usage |
|------|-------|-------------|------------|-------|
| Dominant (60%) | `var(--color-bg)` | `#F5F1E8` | `#171813` | Page background; rule import diff backdrop |
| Secondary (30%) | `var(--color-surface)` | `#E2D7C5` | `#26271F` | Rule editor side panel; category merge preview panel; import conflict diff cards; auto-categorization summary expansion |
| Accent (10%) | `var(--color-accent)` | `#0F766E` | `#0F766E` | Reserved elements only (see below) |
| Destructive | `var(--color-destructive)` | `#B42318` | `#B42318` | Reserved elements only (see below) |

Accent (`var(--color-accent)`) is reserved for:
1. The primary "Save rule" / "Create rule" button in the rule editor panel (single accent CTA per panel).
2. The "Confirm merge" button in the category merge confirmation flow (after preview — this is the committing action).
3. The "Export rules" button's icon tint when export is in progress (active state feedback only).
4. Focused condition row outline ring (`:focus-visible` — `outline: 2px solid var(--color-accent); outline-offset: 2px`).
5. Drag-reorder active drop indicator line between rule rows (`border-top: 2px solid var(--color-accent)` on the target drop slot).

Accent is NOT used for:
- The [+] Add condition button (secondary styling — `var(--color-border)` border, `var(--color-ink)` text).
- Specificity badge (use `var(--color-muted)` for low, a mid-ink value for medium, and `var(--color-ink)` for high — no accent).
- The "Skip" or "Keep existing" buttons in import conflict resolution (secondary/muted styling).
- The ReDoS warning badge (use `var(--color-destructive)` for the badge border and text).
- Drag handle icon (use `var(--color-muted)` — it is structural chrome, not a primary action).

Destructive (`var(--color-destructive)`) is reserved for:
- The ReDoS warning badge on a regex condition row — `border: 1px solid var(--color-destructive); color: var(--color-destructive)` text badge with label "Caution: complex pattern".
- The "Delete rule" action inside the rule editor panel and the rule row context action — destructive text color on hover only (`var(--color-muted)` default, transitions to `var(--color-destructive)` on hover).
- The "Merge category" confirmation panel left border inset — `3px solid var(--color-destructive)` — mirrors the Phase 9 error detail panel grammar for irreversible operations.
- The "Archive category" confirmation prompt — destructive text on the "Archive" action button.
- Category merge and archive inline confirm copy (the consequence statement before the user commits).
- The "Category not found" warning chip on a rule that was imported without a resolved category — `border: 1px solid var(--color-destructive); color: var(--color-destructive)` inline chip.

Color source: `src/renderer/styles/tokens.css` — all values read directly.

## Visuals

Primary focal point per surface:

- **Rule editor side panel (dynamic condition rows):** The condition row list is the dominant visual element. Each row is a horizontal flex strip: drag handle (left, muted) — operator dropdown — value input — delete icon (right, muted). The row reads left to right like a sentence. The [+] Add condition button sits flush below the last row, full-width, so the list feels like a growing document rather than a form section.
- **Rule list with drag handles:** The drag handle (lucide `GripVertical` icon, 16px, `var(--color-muted)`) appears at the far left of each user rule row, always visible (not hover-reveal). System rules have no drag handle and are visually separated from user rules by a labeled divider: `"System rules (applied last)"`. The specificity badge (`"high"` / `"medium"` / `"low"` in a bordered pill, `var(--color-muted)`) appears at the right of each row, after the affected-count metadata. It is informational chrome — small and de-emphasised.
- **Import conflict diff screen:** Each conflicting rule is presented as a single card spanning the panel. The card header shows the rule name at `Heading` size. Below it, two equal-width columns side by side: left labeled `"Current"` (existing rule), right labeled `"Incoming"` (from file). Each column lists the conditions and action as compact label–value pairs at Label size. Three action buttons below each card: `"Keep current"`, `"Replace with incoming"`, `"Skip both"`. Non-conflicting rules are listed below a horizontal rule under a `"No conflicts"` section in compact rows.
- **Category merge preview:** Panel uses `var(--color-surface)` background with `3px solid var(--color-destructive)` left border inset (same grammar as Phase 9 error panel and Phase 8 Danger Zone). Shows: "Merging {source} into {target}" heading, affected transaction count as a prominent number (`fontWeight: 600`), a sample list of up to 5 transactions (Caption size), and a warning that this cannot be undone. "Confirm merge" (accent primary) and "Cancel" (secondary) buttons at the bottom.
- **Auto-categorization summary in import commit screen:** A collapsible disclosure below the import success heading. Default state: collapsed, single-line label: `"{N} transactions categorized by your rules."` at Label size (`var(--color-muted)`). On expand: shows a flat list of rule name → count pairs. Expansion does not push the primary import success CTA off-screen (D-10 intent). If no rules matched (D-11), this section is absent entirely.

## Interaction Contracts

### Dynamic Condition Row List (RULES-01, RULES-02, RULES-03, RULES-08)

- **Condition rows:** Each row in `RuleEditorPanel` maps to one entry in `descriptionTerms`. Initial state for a new rule: one empty condition row with operator defaulting to `"contains"`.
- **Operator dropdown:** `<select>` element, `minHeight: 36px`, options: `Contains`, `Starts with`, `Ends with`, `Regex`. Selecting `Regex` changes the value input placeholder to `"Regular expression (e.g. ^Uber)"` and activates ReDoS detection on input.
- **Value input:** `<input type="text">` filling remaining row width. `placeholder="Value"` for non-regex rows.
- **ReDoS badge:** Rendered inline to the right of the value input when `op: 'regex'` is active and the heuristic flags the pattern. Badge text: `"Caution: complex pattern"`. Badge style: `fontSize: 12` (Caption), `border: 1px solid var(--color-destructive)`, `color: var(--color-destructive)`, `borderRadius: var(--radius-md)`, `padding: 2px 8px`. Does not block saving — warns only.
- **Live match preview for regex:** When `op: 'regex'` and the field is non-empty, a preview line appears below the condition row showing `"{N} transactions match this pattern"` at Caption size, `var(--color-muted)`. Uses the same `RulePreviewPanel` infrastructure used by the existing rule test preview (Phase 5 precedent).
- **[+] Add condition button:** Full-width secondary button below the last condition row. Label: `"Add condition"`. `minHeight: 36px`, `border: 1px dashed var(--color-border)`, `color: var(--color-ink)`, `borderRadius: var(--radius-md)`. Clicking appends a new blank condition row with operator defaulting to `"contains"`.
- **Delete condition icon:** `lucide Trash2`, 14px, `var(--color-muted)` default. Hover: `var(--color-destructive)`. Appears at far right of each condition row. The last remaining row cannot be deleted (icon is `opacity: 0.3`, `cursor: not-allowed`).
- **Amount range section:** Appears below the condition rows section, separated by a `var(--space-xl)` gap and a section label `"Amount"` at Label size. Two inputs: `"Greater than"` and `"Less than"` with `type="number"`, `min="0"`, `step="0.01"`, `placeholder="₹ amount"`. These map to `amountMinMinor` / `amountMaxMinor` in the contract (D-02). Both are optional.
- **AND logic indicator:** A small `"AND"` badge (`fontSize: 12`, `var(--color-muted)`, `border: 1px solid var(--color-border)`, `borderRadius: var(--radius-md)`, `padding: 2px 6px`) sits between each adjacent condition row pair. It is a static label, not interactive — it communicates AND semantics without a UI toggle since OR is out of scope.

### Rule Drag-Reorder (RULES-04)

- **Drag handle:** `lucide GripVertical` icon, 16px, `var(--color-muted)`. Always visible at far left of user rule rows. `cursor: grab`. Active drag: `cursor: grabbing`.
- **Drag interaction:** Native HTML5 `draggable` attribute + `onDragStart` / `onDragOver` / `onDrop` events. State tracked via `useDragReorder` hook holding `dragIndex` / `dropIndex`.
- **Drop indicator:** A `2px solid var(--color-accent)` horizontal line renders between rule rows at the current drop slot. No placeholder ghost row — just the line.
- **Auto-scroll:** If dragging within 48px of the top or bottom edge of the rule list container, the list scrolls at a constant rate (4px per animation frame). No library needed — a `requestAnimationFrame` loop triggered by `onDragOver` proximity check.
- **System rule boundary:** System rules are rendered below a `"System rules (applied last)"` divider. Users cannot drag a user rule past this divider (drag target slots below the divider are not valid drop zones — `onDragOver` calls `event.preventDefault()` only above the divider). The divider itself is not draggable.
- **Persist on drop:** `onDrop` calls `rules:reorder` IPC handler with the new sorted array of user rule IDs. The rule list optimistically reorders before the IPC response to avoid jank.
- **Specificity badge:** Rendered at right of each rule row: `"high"` / `"medium"` / `"low"` pill. Styles: `fontSize: 12` (Caption), `border: 1px solid var(--color-border)`, `borderRadius: var(--radius-md)`, `padding: 2px 8px`. Colors: `"high"` — `color: var(--color-ink)`; `"medium"` — `color: var(--color-muted)`; `"low"` — `color: var(--color-muted), opacity: 0.7`. Tooltip on hover: `"Specificity score: {value}. This does not affect execution order — drag to reorder."` (plain `title` attribute, consistent with Phase 8 shortcut hint pattern).

### Category Rename (RULES-05)

- **Interaction:** Inline edit on the category row — clicking the category name converts it to an `<input>` pre-filled with the current name. `Enter` or blur submits. `Escape` cancels without change.
- **Feedback on success:** The row name updates immediately (optimistic). A transient `"Renamed to {new name}."` line appears below the row at Label size, `var(--color-muted)`, fades after 3 seconds. No modal.
- **Feedback on error:** The input reverts to the old name and an inline error message appears: `"This name could not be saved. Try a different name or try again."` at Label size, `var(--color-destructive)`.
- **Propagation is silent:** The atomic rule target update (D-17) happens in the same IPC call. No secondary confirmation or progress indicator — it is fast and local.

### Category Merge (RULES-06)

- **Trigger:** "Merge into…" action on user category rows (not system categories). Opens a target category picker inline below the category row (not a modal).
- **Target picker:** Searchable dropdown of all active non-archived categories, excluding the source category. Selecting one immediately triggers a `categories:merge-preview` IPC call.
- **Preview panel:** Replaces the picker with the merge preview surface (see Visuals section). Shows affected transaction count (bold `Heading` size number), sample transactions (up to 5, Caption size), and destination confirmation copy: `"All transactions and rules in {source} will move to {target}."`.
- **Confirm CTA:** `"Merge {source} into {target}"` — accent primary button, `minHeight: 44px`. Clicking executes the atomic merge IPC call.
- **Cancel:** `"Cancel"` secondary button closes the preview and restores the category row to its normal state.
- **Success feedback:** The source category disappears from the list. A toast-style inline message at the top of the categories pane: `"{source} merged into {target}. {N} transactions updated."` — disappears after 5 seconds.

### Category Archive (RULES-07)

- **Trigger:** "Archive" action on user category rows. Opens an inline confirmation prompt within the category row (not a modal). No confirmation for system categories — they cannot be archived.
- **Confirmation copy:** `"Archive {name}? Its transactions stay intact, but the category won't appear in pickers."` at Label size.
- **Actions:** `"Archive"` (destructive text button) and `"Keep"` (muted text button) side by side.
- **Post-archive:** The category row is removed from the active list. A `"Archived categories"` disclosure section at the bottom of the categories pane shows archived items in a collapsed list. Expanding shows each archived category with a `"Restore"` button (secondary pill, `fontSize: 12`, Caption role).
- **Picker behavior:** Archived categories are excluded from all category pickers (rule editor, transaction edit, bulk categorize). They remain queryable and display correctly on existing transactions in the ledger.

### Rule Export (RULES-09)

- **Trigger:** `"Export rules"` button in the `RuleExportImportBar` component rendered above the rules list. Secondary pill button. Icon: `lucide Download`, 14px. Label: `"Export rules"`.
- **Behavior:** Calls `rules:export` IPC → Electron `showSaveDialog` with default filename `"walnut-rules-{YYYY-MM-DD}.json"`. File format: JSON array (D-14). System rules excluded.
- **Success feedback:** Button shows `"Exported"` label for 2 seconds then reverts. No modal.
- **Empty state:** If the user has no user rules, the button is disabled with `title="No rules to export"`.

### Rule Import (RULES-10)

- **Trigger:** `"Import rules"` button adjacent to `"Export rules"` in `RuleExportImportBar`. Secondary pill button. Icon: `lucide Upload`, 14px. Label: `"Import rules"`.
- **Behavior:** Calls `rules:import` IPC → Electron `showOpenDialog` (JSON files only). The IPC handler parses the file, resolves categories by name (D-15), and detects conflicts by rule name match (D-16).
- **"Category not found" warning:** If any imported rule has an unresolvable category, a warning chip appears at the top of the import result screen: `"Some rules were imported without a category — the category '{name}' was not found."` (one chip per unresolved name). Chip style: `border: 1px solid var(--color-destructive)`, `color: var(--color-destructive)`, `fontSize: 14` (Label), `borderRadius: var(--radius-md)`, `padding: 4px 12px`.
- **Conflict diff screen (`RuleImportDiffView`):** Replaces the rule list pane content (no full-screen takeover) when conflicts exist. Each conflict card layout described in Visuals section above. Non-conflicting rules are listed below in a `"No conflicts — will be added"` section. A `"Confirm import"` accent primary button at the bottom applies all resolutions. `"Cancel import"` secondary button discards all and returns to normal rule list.
- **No-conflict path:** If no conflicts exist, import completes immediately without opening the diff screen. A transient success message appears: `"N rules imported."` at Label size, `var(--color-muted)`, fades after 3 seconds.
- **Empty-state copy for diff screen when there are no conflicts (Claude's Discretion resolved):** The `"No conflicts"` section shows: `"All {N} rules are new — no overlap with your existing rules."` at Label size, `var(--color-muted)`. This is shown only when transitioning through the diff screen programmatically; in practice, no-conflict imports skip the diff screen entirely (see no-conflict path above).

### Auto-Apply at Import Commit (RULES-11)

- **Location:** `ImportSummary.tsx` — the screen shown after a successful import commit.
- **Collapsible disclosure:** A `<details>` / `<summary>` element (or equivalent controlled open/closed state) below the primary success heading. Default state: collapsed (D-10 intent — CTA stays visible).
- **Summary line:** `"{N} transactions categorized by your rules."` at Label size (`fontSize: 14`, `color: var(--color-muted)`). Only shown when `N > 0` (D-11).
- **Expanded content:** A flat list of `"{rule name} — {count} transaction{s}"` rows at Caption size inside the disclosure body. Uses `var(--color-surface)` background, `var(--space-md)` padding. Max height: `180px` with `overflow-y: auto` if the list is long.
- **Expand/collapse toggle:** `lucide ChevronDown` / `ChevronUp` icon (12px) at the right of the summary line, rotates on state change. `transition: transform 140ms ease`.

Tone rules (consistent with project):
- Plain, direct, household-owner voice. No marketing language.
- Consequence before action: state what will happen, then offer the action.
- Destructive confirmations name the specific subject (`{name}`, `{source}`, `{target}`) — never generic.
- Count confirmations are exact ("3 transactions" not "some transactions").
- Avoid "smart", "magic", "auto-fix", "instantly", and "automatically" — prefer "match", "apply", "categorized", "assigned", "affected".
- "Caution" over "Warning" or "Error" for non-blocking advisories (ReDoS badge).
- Technical terms ("Regex", "AND") are acceptable — this is a power-user surface.

## Accessibility Contract

1. All interactive elements reach via Tab in logical document order.
2. Focus ring visible on every focusable element (`:focus-visible` — `outline: 2px solid var(--color-accent); outline-offset: 2px`).
3. Condition row operator `<select>` has `aria-label="Condition {N} operator"` where N is the 1-based row index.
4. Condition row value `<input>` has `aria-label="Condition {N} value"`.
5. Delete condition icon button has `aria-label="Remove condition {N}"`.
6. Drag handle has `aria-label="Drag to reorder {rule name}"`. The rule list container has `role="list"` and each row has `role="listitem"`.
7. Drag-and-drop keyboard fallback: drag handle also responds to Space/Enter to enter reorder mode, then arrow keys to move, then Space/Enter to confirm drop. This does not require a library — a small keyboard handler mirrors the HTML5 drag semantics for accessibility.
8. System rule divider: `role="separator"` with `aria-label="System rules (applied last)"`.
9. Specificity badge: `aria-hidden="true"` — the same information is conveyed in the tooltip on focus/hover; the badge itself is decorative chrome.
10. Category merge preview panel: `role="region"` with `aria-label="Merge preview: {source} into {target}"`. Sample transaction list is a `<ul>`.
11. Category inline rename input: `aria-label="Rename category"`, `autoFocus` on mount. `Escape` cancels without data loss.
12. Import diff view: `role="region"` with `aria-label="Import conflict review"`. Each conflict card is a `<section>` with the rule name as the heading.
13. `"Category not found"` warning chips: `role="alert"` so screen readers announce them without requiring focus.
14. Auto-categorization summary `<details>` element: `<summary>` text includes the full `"{N} transactions categorized by your rules."` copy — the icon rotation is `aria-hidden="true"`.
15. Archived categories `<details>` element: `<summary>` text: `"Archived categories"`.
