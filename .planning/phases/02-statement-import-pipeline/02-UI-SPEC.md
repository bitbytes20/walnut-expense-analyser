## Import Flow Contract

### Entry Points
- Support two entry surfaces only in Phase 2: the dashboard empty-state primary CTA and a dedicated `Import Statements` screen route.
- Both entry points must land in the same import workspace; do not create separate empty-state and full-screen import implementations.
- Keep the existing branded shell chrome visible throughout the import flow so the experience feels like a trusted product workflow, not a detached utility dialog.

### Import Workspace Layout
- Use a desktop-first two-zone content layout inside the existing shell.
- Left zone is the active task column with a maximum width of 760px.
- Right zone is a contextual guidance column with a maximum width of 320px for supported-format guidance, privacy reminders, and prior-batch references.
- Collapse to a single-column stack below 1100px width, with the guidance column moving below the task column.
- Cap the overall content width at 1180px.

### Staged Batch Flow
- Use a fixed staged sequence: `Select files` -> `Review staged files` -> `Resolve sheet choice if needed` -> `Import summary`.
- Do not begin parsing immediately after file picker selection. Files must first appear in a staging view with per-file status rows.
- Treat multi-file selection as a curated batch. Each file row must remain independently understandable and independently actionable.
- The staging view is the primary visual anchor of the phase. It must clearly separate `Ready`, `Needs sheet selection`, `Rejected`, and `Duplicate blocked` states.
- Use section headings in plain language, not tabs. The staging screen should read like a controlled checklist rather than a dashboard analytics view.

### File Row Contract
- Each staged file row must show: filename, file type badge, detected account label if available, statement period if detectable, and status.
- Keep file rows as full-width cards with a strong left-to-right scan order: file identity, support details, status, row action.
- Row actions must be context-specific:
- `Review sheet` for multi-sheet Excel files
- `View reason` for rejected files
- `View earlier batch` for duplicates
- `Remove` for any staged file the owner does not want to continue with
- Rows in `Rejected` and `Duplicate blocked` states must remain visible in the batch instead of disappearing after failure.

### Worksheet Choice
- Present worksheet choice as an in-flow side panel or inline expansion from the file row, not as a separate route.
- Show worksheet names in a selectable list with a short preview line for each candidate, such as date range, row count, or detected columns when available.
- Mark the best candidate as `Recommended`, but never auto-advance when more than one plausible worksheet exists.
- Allow only one worksheet selection per file in Phase 2.

### Import Summary
- After batch processing, land on a summary state inside the same import workspace.
- Group results into `Imported`, `Rejected`, and `Duplicate blocked`.
- For imported files, show counts for files imported and transactions created.
- If the first successful import auto-creates the ICICI account profile, show that confirmation inline in the summary header.
- If every selected file failed, the summary must still render as a proper result screen rather than dropping the owner back to the empty dashboard without context.

## State and Feedback Contract

### Validation and Trust
- Validation language must be specific and investigative. Name the failure reason instead of using generic `invalid file` copy.
- Unsupported-format errors must explain what was expected, such as `Use an ICICI account statement in CSV, XLS, or XLSX with transaction date, narration, and debit or credit columns.`
- Best-effort parsing may accept non-exact templates, but the UI must never describe this as guesswork or automatic fixing.
- Balance continuity concerns are warnings, not blockers, in Phase 2. Show them as `Check after import` notices in the imported-file result area.

### Loading and Progress
- Show progress at batch and row level.
- Batch header shows aggregate progress such as `2 of 5 files processed`.
- Each file row shows one transient state only: `Preparing`, `Parsing`, `Checking duplicates`, or `Imported`.
- Do not use a full-screen spinner. The rest of the batch must stay readable while processing continues.
- Primary action loading labels must be explicit, such as `Preparing files` or `Importing statements`.

### Success, Warning, and Error States
- Use inline summary banners inside the workspace rather than toast-only outcomes for import results.
- Success styling should stay restrained and trust-oriented; reserve celebratory language and illustration treatment for later phases.
- Warning styling is for soft balance discontinuity checks and worksheet ambiguity only.
- Destructive red styling is reserved for irreversible cleanup actions and hard rejection summaries, not for every parse issue.
- Duplicate blocked messaging must include the reason, the earlier batch reference, and an immediate path to inspect that earlier batch.

### Privacy Messaging
- Show a persistent helper line in the guidance column during selection and staging: `Statement files are read for import and are not stored by Walnut.`
- Do not imply cloud upload, background sync, or retained attachments anywhere in the flow.
- If temporary parsing work is mentioned, phrase it as on-device processing only.

### Keyboard Contract
- `Tab` and `Shift+Tab` must traverse the full staging list, row actions, and worksheet options in visual order.
- `Enter` activates the primary page action only when a focused textless control is not intercepting it.
- `Esc` closes an open worksheet-choice panel or reason panel without abandoning the batch.
- File picker trigger must be keyboard reachable from both import entry points.
- After choosing files, focus moves to the staging heading.

## Component Inventory

- `Import workspace header`: title, supporting privacy copy, batch progress, and primary action.
- `Staged file row card`: reusable for ready, rejected, duplicate, processing, and imported states.
- `Status badge`: ready, warning, blocked, success, or processing.
- `Worksheet choice panel`: selectable list with recommended state and confirm action.
- `Reason panel`: compact explanation block for rejection and duplicate details.
- `Guidance card`: supported-format checklist, privacy reminder, and account-scope reminder.
- `Import summary group`: grouped result list with counts and next-step actions.

Use the Phase 1 card language: rounded large surfaces, soft border, muted secondary backgrounds, and accent only for primary emphasis.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Import statements |
| Empty state heading | Bring in your ICICI statements |
| Empty state body | Select one or more ICICI statement files to stage them, review any issues, and import the records without storing the source files. |
| Error state | This file could not be imported. Review the reason below, confirm it is an ICICI CSV, XLS, or XLSX export, and try again with a supported statement. |
| Destructive confirmation | Remove file from batch: This only removes the staged file from the current import and does not delete anything already imported. Continue? |

Microcopy rules:
- Lead with trust and scope. Prefer `stage`, `review`, `import`, `blocked`, and `not stored`.
- For duplicates, reference the earlier batch directly rather than saying the file is simply not allowed.
- For invalid files, explain the missing or unsupported structure before telling the owner to retry.
- Avoid hype language such as `smart`, `magic`, `auto-fix`, or `cleaned up for you`.
